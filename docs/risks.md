# 风险与待验证项｜ORCA 治理母版

> 常驻风险位：只记「还没解决、或解决前会咬人」的事。已解决的历史问题进 `docs/history/`，踩坑手法进 `agent.md`。
> 上限 100 行 / 8,192 字节。每条写：风险 → 影响 → 触发条件 → 处置。

## 1. 高影响

### R1 老项目长期跑旧规则
- 影响：存量 30+ 个项目沿用旧 `AGENTS.md`，与本仓规则漂移，`DEPENDENCY-STALE` 会持续报警。
- 触发：对老项目做治理检查或迁移时。
- 处置：2026-10-22 既定口径「老项目不铺、不管」，只有用户另行拍板才批量重注入；单项目更新只能用 `ONLY_LIST`。

### R2 母版账本一旦写入真实行
- 影响：`check-sync.sh` 直接 `SYNC-FAIL`，整条分发链断。
- 触发：有人把真实 Episode／派工写进母版 `docs/model/*.jsonl`。
- 处置：母版只保留 `_example` 空壳；真实记账写各项目自己的账本。

### R3 全局规则软链与母版位置绑定
- 影响：`~/.agents/rules/*.md` 与各项目根 `USER_MODEL_OVERRIDE.md` 都是指向母版的**绝对软链**；母版一搬家、或外盘未挂载，规则静默失效（读到空内容或断链）。
- 触发：母版目录改名/迁移；外盘卷未挂载时访问迁移出去的项目；换机后未重建软链。
- 处置：`background-services.md` 已改为指向治理仓 `docs/sop/`（2026-10-31 复验可读）；母版搬家必须同批重建全部软链并逐条 `test -e`；2026-10-31 已重建 6 条用户级 + 44 条项目级。

### R4 Skill 依赖声明缺失导致新规则落空
- 影响：7 颗 Design Pipeline Skill 用相对路径引用 `docs/sop/app-*.md`，落到项目本地副本；新建/改动 SOP 未同步给 Skill 加条件式依赖声明，则规则写了也不生效。
- 触发：新增或改名 `docs/sop/app-*.md`。
- 处置：同批修改 Skill 依赖声明，并跑 7-Skill validator。

## 2. 中影响

### R5 简化门槛尚未实战验证
- 影响：Gate A 六项、Gate B《可删减项清单》、Gate D 证据分级只在纸面通过，未在真实 APP Phase1 走通。
- 触发：下一个面向用户的 APP 进入 Phase1。
- 处置：首次实战时逐项核对，结果回写本文件或 HANDOFF。

### R6 产品验收矩阵覆盖不足
- 影响：红线要求「产品验收未落盘不得报完工」，但巡检显示多数存量项目缺 `docs/qa/产品验收追踪矩阵.md`。
- 触发：存量项目收尾。
- 处置：`check-sync` 只报不阻塞；逐项目补或由用户明确豁免口径。

### R7 角色账本覆盖缺口
- 影响：`ROLE-COVERAGE` 巡检点名多个项目缺 `code-reviewer`／`qa`／`supervisor` 行，账面看不出复核发生过。
- 触发：审计或交接。
- 处置：只报不阻塞；由各项目自行补记，治理侧不代改。

### R8 存量项目账本字段不合规
- 影响：`date` 非真实日历、`used` 未填主、枚举越界等，会让 `check-ledger` 报警。
- 触发：在那些项目里跑校验。
- 处置：各项目自行按新标准改并自检；历史实绩用「更正行」而非改写。

## 3. 低影响 / 观察项

- **R9 母版搬迁未做**：用户明确「先不要动」；搬迁需处理 15 个旧项目软链。
- **R10 测试 pass 数漂移**：用例增补会让历史文档里的数字过期；一律以脚本实际输出为准。
- **R11 铺包脚本的模板实例化**：新增根级模板若漏进 `TEMPLATE_DIRS` 或恢复路径，项目会缺文件而不报错，靠 `check-sync` 与恢复验收兜底。

### R9 迁到外盘的项目依赖卷挂载
- 影响：`1.Active/<项目>` 是外盘软链（`项目归档` 为 sparseimage 挂载卷），卷未挂载时项目不可读、`USER_MODEL_OVERRIDE.md` 与治理检查全部失效，`find` 类批量扫描还会静默漏掉整批项目。
- 触发：移动硬盘未插、镜像未挂载、换机首启。
- 处置：动这些项目前先确认卷已挂载并 `realpath` 抽样；批量核对引用必须解软链，不能只扫 `1.Active` 字面目录。
