- **P1｜关键 AC 范围无法机械确定**
  - 文件：`docs/pm/PRODUCT_PLAN.template.md:17-19`、`docs/qa/BUGS.template.md:9`、`docs/roles/qa.md:18-19`、`docs/roles/supervisor.md:51`

  - 唯一推荐改法：Plan 每条 AC 增加必填“关联 User Flow 任务 / 关键（是/否）”，矩阵保留该关联或关键标记，使 QA 与 supervisor 使用同一显式集合。

- **P2｜关键路径兜底条件的适用范围有歧义**
  - 文件：`docs/roles/qa.md:18`、`docs/pm/PRODUCT_PLAN.template.md:9`
  - 可复现证据：规则一方面以“计划 User Flow 的关键用户任务”为核心，另一方面仅在“计划未标注时”将 User Flow 全量视为核心；未说明 User Flow 缺失、或有 User Flow 但未标注关键任务时是否触发兜底。
  - 唯一推荐改法：明确“User Flow 未标记关键任务或缺失时，所有已列 User Flow 任务按核心处理；User Flow 缺失则 QA 阻塞并退回补计划”。
